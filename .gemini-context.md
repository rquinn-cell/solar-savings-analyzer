# Project Context & Environment Rules: Solar Savings Analyzer

## 1. Core Architecture & Stack
- **Project Name:** solar-savings-analyzer
- **Frontend / UI:** Streamlit (`streamlit run app.py`)
- **Backend / Database:** Supabase Python SDK
- **Testing Framework:** Test-Driven Development (TDD) using `pytest`
- **Primary Domain:** Parsing Xcel energy bill data formats, analyzing baseline vs. potential solar savings configurations.

## 2. Machine & Local Environment Constraints
- **Host OS:** ChromeOS Linux (Crostini Container)
- **Base System Python:** 3.11.2 (Managed by Debian packages)
- **Isolated Project Python Execution Environment:** - **Runtime Version:** Python 3.13.9
  - **Toolchain Distribution:** Packaged by Anaconda, Inc. (Miniconda3)
  - **Local Bin Path:** `~/miniconda3/bin/activate`
  - **Project Directory Sandbox:** Local `.venv` tracking directory.
- **Critical Context Rule:** Do NOT attempt to alter the host machine's default Python 3.11 bindings. The workspace *must* remain bound to the custom compiled 3.13.9 Miniconda stack to maintain stability for modern dependencies (Streamlit/Supabase).

## 3. DevOps, Backup & Issue Pipelines
- **Workstation Security Net:** Full-system file and dependency backups are handled via manual/incremental **Restic** snapshots targeting local mount vectors mapped to Google Drive (`/mnt/chromeos/GoogleDrive/MyDrive/LinuxBackups`).
- **Automated Agile Backlog Pipeline:** - Active issues are cleanly decoupled from deprecated GitHub "Projects (classic)" structures.
  - Tracking tickets are mirrored locally to the project workspace using a custom synchronization utility (`./sync_issues.sh` or the global alias `sync-issues`).
  - Active tickets live as static markdown templates at `.github/issues/issue-*.md`.
- **Authentication Scope:** GitHub access token requires explicit `read:org` scopes alongside personal repo access to dynamically map issues. Valid for 90-day intervals.
